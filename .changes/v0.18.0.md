## v0.18.0 (2026-11-26)

v0.18.0 adds one function to `appdirs`, `Volume`, which answers what kind of volume holds a path, `Local`, `Network`, `FUSE`, `SyncPlaceholder` or `Unknown`, so a program that keeps a database or a lock file there can refuse a volume whose locks and fsync it may not trust; only `Local` reads as local, and an error and `Unknown` are separate answers. It adds one to `write`, `LogWriter`, an `io.Writer` over `Append` for `log/slog`'s handlers and other line loggers, which appends each whole line through `Append` and refuses a Write that does not end in a newline. Neither macOS's File Provider detection nor Windows' Cloud Files detection is yet proved on a real domain or sync root, and until the run of go-files#19 proves them, a caller should take `SyncPlaceholder` on macOS and Windows as best effort. `Local` says what the system mounts: a sync client that keeps a plain folder as whole files, and a network behind the block device, are not seen. The pre-push tier is now judged by its CPU time. No exported name is removed, moved or changed.

The full release checks, `task release`, ran on macOS at the tagged commit. On Linux, macOS and Windows, the test workflow ran at the tagged commit in CI: go vet, the tests with the race detector, lint, the API check and the vulnerability check. No full release checks ran on Linux or Windows for this release.

### Added

- appdirs.Volume(path) answers what kind of volume holds a path, links followed, as an appdirs.VolumeInfo: Type, the system's own name for the file system, and Kind, one of appdirs.Local, Network, FUSE, SyncPlaceholder and Unknown. VolumeInfo.Local() is true for Local alone; the zero VolumeKind is Unknown, and an error comes with the zero VolumeInfo, so neither reads as local. Removable disks are Local. What is detected where: macOS asks statfs's type name and local-mount flag: APFS, HFS+, FAT and exFAT with the flag are Local, a type that holds fuse is FUSE whatever the flag says, NFS, SMB, AFP, WebDAV, CIFS and FTP are Network, FUSE-T among them, as it mounts through NFS or SMB, and a path in a File Provider domain, told by an attribute that the system's domain mark or com.apple.fileprovider. leads, on it or a folder above it, or an evicted file, is SyncPlaceholder. Linux asks statfs's magic number, which alone decides, and the mount table's fstype for Type, fuse.sshfs and other FUSE subtypes among them: ext2 to ext4, XFS, btrfs, f2fs, tmpfs, ZFS, FAT, exFAT, bcachefs and overlay are Local, NFS, SMB, CIFS, AFS, Ceph, Coda and 9p Network, and FUSE FUSE; Linux keeps no sync placeholders. overlay is Local, as a container's root needs, whatever its layers are on: an overlay whose upper layer is FUSE, virtiofs among them, is Local, where the upper folder asked itself is FUSE. Windows asks the volume's NT device, drive type and file system name: a remote drive or a \Device\Mup path is Network, a file system whose name holds FUSE is FUSE, and only NTFS, ReFS, FAT and exFAT on a numbered local disk volume, fixed or removable, under no sync root, Local; a path is SyncPlaceholder where it or a folder above it, up to the volume's root, each opened with no link followed, carries an IO_REPARSE_TAG_CLOUD reparse tag or one of its variants, or where a sync root registered under the SyncRootManager key holds it, matched by whole names with no case. The Cloud Files API's CfGetSyncRootInfoByPath is not asked, as go-files reaches no DLL's call by name. The macOS File Provider detection is not yet proved on a real domain, nor the Windows Cloud Files detection on a real OneDrive sync root, as no runner they are tested on has one: on macOS, iCloud's Desktop and Documents sync keeps ~/Desktop and ~/Documents outside both Library folders, so where those carry no mark they read Local; on Windows the Cloud Files filter can disguise placeholders from a process that has not opted in to seeing them, so the tag half may never see a tag, and the registry half matches a root only as the registry spells it. Until the run of go-files#19 (https://github.com/birdtable/go-files/issues/19) proves them, a caller that must not run on a sync folder should take SyncPlaceholder on macOS and Windows as best effort. Local says what the system mounts and no more, so these read Local: a plain folder a sync client keeps as whole files, with no placeholder and no mark, Dropbox on Linux, Syncthing and a mirror-mode folder among them, and a local file system on a block device the network serves, a disk image or sparse bundle on a share, iSCSI or NBD, a loop file on NFS and a VHDX opened from a share among them. What reads as Unknown: on macOS a path below Library/CloudStorage or Library/Mobile Documents with no mark, each name matched by Go's simple case folding, not the file system's, so another spelling the file system takes for the same folder, a ligature for st among them, is not seen, a path whose folders' attributes cannot be listed, a volume without the local-mount flag that is neither FUSE nor network, and any other type, devfs among them; on Linux any other magic number, procfs, sysfs and the kernel's NTFS among them; on Windows a path whose reparse tags or the registered sync roots cannot be read, another device, a WinFsp or Dokan drive that names itself NTFS among them, another drive type and another file system. Any other system, FreeBSD among them, is an *fs.PathError matching errors.ErrUnsupported. Non-test Go lines, as task size counts them: appdirs 949 to 1,545, 596 more, the 111 of volume.go, the rules of each system in volume_rule.go, a file for macOS, Linux, Windows and the other systems, and 1 of the package doc.
- write.LogWriter(ctx, root, name, limit, opts...) is an io.Writer over write.Append, for log/slog's handlers and other line loggers. Each Write must hold whole lines, each ending in a newline, and each line goes through Append with the writer's ctx, cap and options, so each is one write and the cap holds line by line. A Write that does not end in a newline, an empty one included, is refused with an error matching fs.ErrInvalid, nothing of it written and nothing kept back; a Write that fails on a line returns the bytes of the lines before it and writes none after. The ctx is the writer's for its whole life, as io.Writer's Write takes none.

### Changed

- The pre-push tier is judged by the CPU time its tree uses, user plus system, through hatch budget --cpu: on macOS arm64 it fails over 322 s, twice the least of three runs from a fresh clone, each after go clean -testcache (160.6, 164.7 and 165.4 s). CPU time is the same on a quiet machine and a loaded one, so the load no longer excuses a push. Its wall budget of 10 s is only a hang guard: a push past it and within its CPU limit passes, saying so, and one still running at 100 s is killed and fails as hung. The commit and release tiers keep their wall-time budgets.

### API

Against v0.17.0, no exported name is removed, moved or changed: the API check's breaks from v0.17.0 to v0.18.0 have no lines, alike on darwin, linux and windows.

Added, each `experimental`: in `appdirs`, `Volume`, `VolumeInfo` with its method `Local`, `VolumeKind` with its method `String`, and the constants `Unknown`, `Local`, `Network`, `FUSE` and `SyncPlaceholder`; in `write`, `LogWriter`.
